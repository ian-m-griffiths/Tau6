## 3. Counter-to / reversal edges

- **"Ternary is more efficient than binary" is only true for specific symbol counts**: Table 4 shows binary is superior when the number of symbols is NOT a power of 3 ("as it is a larger set, ternary coding is more efficient than binary only for specific values"). Counter-to the blanket opening claim; matches TERNARY_PROCESSOR.md's own caveat that the engineering conclusion is contested.
- **Range counts flip-flop between bases 2 and 3** depending on proximity to 2ⁱ−1 vs 3ⁱ−1 (Table 2) — the "ternary wins" headline is not uniform over ranges.
- **Non-uniform symbol probabilities increase binary's advantage** in decision trees — more realistic workloads favor binary, the reverse of the uniform-probability intuition.
- **The optimal base is irrational (e)**: ternary is only *near*-optimal, so "optimal coding" is literally unattainable in integer bases — the philosophical reversal (N11) is that this is a *limitation of mathematics*, not a design bug.
- **Binary is more efficient for first digits** (Benford) — even within the same coding frame, the "larger alphabet wins" intuition fails.
